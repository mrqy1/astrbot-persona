# 模块写作指南（BUILD GUIDE）

> 给想「新建一个特质模块，或想把现有模块改得更好」的人看。读完 + 对着 `傲娇.md` 看一遍，就能自己产出同质量模块。

## 0. 一句话原则

**模块 = 人设 + 机制 + 参数 + 例子 + 界。** 五个要素缺一个，这模块就不好用。

---

## 1. 好模块的 5 条质量线（写完自检用）

| # | 质量线 | 说明 | 对的例子 |
|---|--------|------|----------|
| 1 | **有参数**（能调强度） | 模块顶部必须有「可调参数」，数值给默认值 | `傲娇程度：70%` |
| 2 | **有机制**（能干活） | 不只是描述性格，得有"怎么在对话里动起来"的规则 | 状态切换引擎、触发条件 |
| 3 | **有例句**（AI 抄得走） | 每条行为尽量给一句话当作范例 | `"哼，谁要你管"` |
| 4 | **有界**（有红线） | 明确 AI 不能越哪个界 | `绝不直接说我喜欢你` |
| 5 | **有组合**（能和别模块共存） | 写明跟别的模块怎么叠 | 冲突裁决一节 |

> 🔍 自检：拿你自己的模块对着这 5 行过一遍，哪条没满足就是短板。

---

## 2. 标准骨架（推荐 8 段，写新模块照这个顺序）

```
# 【性格模块：名字】
> 使用说明：复制本文件全部内容，粘贴到你的 persona.md 里。内文都是 AI 直接执行的。

## 一句话人设         ← AI 心里记住的定位（1 句，别长）
## 可调参数            ← 3~4 个参数：强度 / 触发对象 / 切换难易度/时长
## 核心行为规则       ← 4~6 条，写"AI 必须遵守"的硬规则
## 状态切换 / 触发    ← 如果有多个状态，写清 触发条件→切换到哪→表现
## 说话风格          ← 3~6 个情境 + 原句例句
## 场景反应指令      ← 表格：什么情形→该怎么做→禁止做什么
## 与其他模块的冲突裁决 ← 叠别的模块时谁让谁
## 红线              ← 绝对不准出现的行为
```

对照：仓库里的 `傲娇.md` 完全符合这个骨架，缺的就是你新模块的四个不同内容（人设/机制/例句/界）。

---

## 3. 常见错（新手 90% 掉进这 4 个坑）

| 错 | 例子 | 怎么改 |
|---|---|---|
| **写形容词不写行为** | `她是可爱的` | → 写机制：反应慢半拍→先发呆再回答 |
| **没参数** | `她傲娇` 就结束了 | → 加 `傲娇程度 70%`，让用户能调 |
| **没有界** | 怎么演都行 | → 写「红线」：不许直白承认喜欢 |
| **跟别模块打架** | 叠了傲娇又叠直球 | → 每个模块都写要冲突裁决，谁让谁写清楚 |

## 4. 可调参数怎么写（最重要）

参数是模块的"旋钮"。写法模板：

```
- 【参数名】：默认值%（数值越高 = 行为越强）
  说明：调高/调低各是什么效果
  切换难易：高/中/低（越高越难触发，越低越容易）
```

举例（傲娇模块的真实写法）：
```
- 傲娇程度：70%（数值越高越嘴硬、越爱否认）
- 触发对象：仅对〔指定关系人/重要的人〕表现出傲娇，其他正常
- 娇面难度：中（越低越容易害羞展露娇面，越高越爱死撑）
```
> 每个参数必须同时给：**默认值 + "调高变什么、调低变什么"**。否则用户改参数没有方向盘。

## 5. 收尾清单（做新模块前最后过一遍）

- [ ] 五要素都在：参数/机制/例句/界/组合
- [ ] 头部有「使用说明」提示复制后粘贴
- [ ] 每条例句都像「AI 说得出口」而非「介绍文案」
- [ ] 红线是真红线（没说错、不能反悔）
- [ ] 和现有任意模块叠时，冲突裁决一节说清了谁让谁
- [ ] 文件放 `modules/` 下，随手在 `modules/README.md` 的表格里加一行

（如果你只是给现有模块改参数文案，通常只需要动「可调参数 + 说话风格」两节。）
